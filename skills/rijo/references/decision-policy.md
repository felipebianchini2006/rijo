# Decision policy

Make technical and reversible decisions automatically.
Use this evidence order:

1. Approved scope and acceptance criteria.
2. Current behavior and tests.
3. Codebase architecture and conventions.
4. Security and data integrity.
5. Official stack documentation.
6. The simplest reversible option.
7. Required scale for the current milestone and the next likely milestone.

Do not ask about internal names, file placement, component patterns, test strategy, error handling, loading states, cache design, logging, or reversible architecture.

Stop only when a missing factual rule or authorization affects money, permissions, legal duties, production data destruction, a paid external service, an irreversible contract, or required credentials.
Ask one factual question.
Do not show an option menu.
